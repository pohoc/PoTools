# 98 项工具交互审计矩阵（静态版）

> 审查基线：`88acacba375f25a6f3980a1faacc03cf5b4cebb9`。数据由 `packages/core/catalog/*.json`（14 份 catalog）逐项对照产生，工具 ID 98 个且无重复。本表是**目标体验建议**，并非已经用 GUI 实测确认的缺陷清单。

## 阅读规则

- **当前登记**只描述 catalog 的 `layout / interaction` 元数据；`action` 包含未显式声明 interaction 的默认行为。
- **优化方向**和**建议执行方式**是要验证/实现的目标，不等同于说当前工具缺少某项能力；请实际打开页面、录制使用路径并标注截图后再定最终方案。
- “实时”仅用于廉价本地计算；“防抖实时”必须隔离过期结果；手动执行适合写文件、联网、昂贵处理；随机生成器分开首次显示与主动重新生成。
- **验收重点**用于后续测试；`P1` 表示优先影响基本任务流程 / 可信性，`P2` 为体验改进。权限类阻断见 [风险账本](IMPLEMENTATION_GAPS.md)。
- 七种模型解释见 [工具交互规范](../standards/TOOL_INTERACTION.md)，元数据方案见 [RFC-0001](../rfcs/0001-tool-experience-contract.md)。
- 本版所有行初始状态为 **待实测 / 未实施**；后续 PR 需附运行环境、截图/样例和验收结论才可标记已验证。

**覆盖统计**：98 工具、49 个文本 layout、49 个非文本 layout；页面管理 6、标注 3、文档信息 3、优化 3、转换 13、页面版式 5、提取 / OCR 4、发票整理 1、图片 9、时间 9、密码学 19、财务 1、开发辅助 9、网络 13。按优先级 P1 64 / P2 34。

## 从矩阵到实施的转化规则

1. 先按七类模型各选一个代表工具打样（`json-format`、`jwt`、`cron`、`password-gen`、`image-crop`、`merge`、`invoice-organize`），产出可运行参考实现与真实用户验收记录。
2. 每个工具先完成现状确认：运行平台、主要操作路径、截图、错误/空值、回归样例；记录「实际差距」，而不是照表直接改 UI。
3. 修改本表相应条目的目标模型与验收口径后，按工具域分 PR 交付；不得一口气替换 98 个工具而失去回归线。
4. 工具状态可追加字段 `Observed / Target / In progress / Verified`，`Verified` 必须附 PR / commit / 测试证据。所有平台差异须明确记录。
5. 宿主权限、任务取消、临时清理等功能缺陷优先于视觉重构，不得因为展示改进掩盖风险。
