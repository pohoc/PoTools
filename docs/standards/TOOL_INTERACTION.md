# 全工具交互规范（Tool Interaction Standard）

**适用**：98 个目录工具及后续新增工具；与 [98 项矩阵](../audits/TOOL_UX_MATRIX.md) 共同使用。**状态**：目标设计规范，尚未声称已实现；对现有行为的判断以源码及实际用户测试为准。

## 0. 核心原则

**使用者应先看到任务，再看到参数；先得到可使用的结果，再看到导出文件。**

1. **一工具一主任务**：标题下以一句动词说明用户能完成什么；主输入和主结果必须处于第一视线区。
2. **操作匹配任务**：结构化解码用结构面板，计算用结果卡，可视化操作用画布，批处理用队列，不能只把通用表单换配色。
3. **渐进披露**：常用项可见，高级项折叠；危险/不可逆选项须在执行前说明后果。
4. **可预测反馈**：选择→校验→预览（可用时）→执行→结果；无效、运行中、空结果、过期、失败和取消都有明确状态。
5. **本地优先与诚实能力**：离线可运行的操作不调用网络；联网能力醒目标识；浏览器和 Tauri 不支持的动作不能以灰按钮或无提示失败糊弄。
6. **保留用户控制权**：需要写入文件、覆盖、删除、网络请求或耗时处理的操作默认 `manual`；不能因字段更新就自动写磁盘。
7. **可访问**：键盘可完成等价操作，焦点顺序合理，错误与成功由 ARIA 文本表达，不只靠颜色。
8. **演进可测**：基于任务完成率、首次运行成功率、步骤数、误操作、键盘覆盖和耗时做评估，而非只看截图。

## 1. 交互模型（七类，可组合）

| 类型 | 典型工具 | 主输入 | 主结果 | 主动作 | 不应出现 |
| --- | --- | --- | --- | --- | --- |
| `instant-transform` 即时转换 | JSON/XML、Base64、大小写、编码转换 | 编辑器 / 输入框 | 同屏可选复制的输出编辑区 | 输入即更新，必要时防抖 | 每次输入必须再点“运行”、结果先渲染下载文件 |
| `structured-inspector` 结构解析 | JWT、X.509、User-Agent、URL/IP | 粘贴结构化值 | 属性分组、验证结果、来源说明 | 粘贴即解析；验签需显式语义 | 原始长文本报告作为唯一结果 |
| `calculator` 计算分析 | 日期差、时间戳、Cron、IPv4 子网 | 语义分组控件 | 大数字/时间表/字段说明 | 轻量联动更新 | 所有参数挤在单个高级选项折叠面板 |
| `generator` 生成器 | UUID、密码、TOTP | 生成策略/密钥 | 一条或多条高可读结果 | 生成、复制、重新生成；TOTP 到期刷新 | 无故反复自动重生密码使用户无法复制 |
| `visual-editor` 可视化编辑 | PDF 页面组织/裁剪、图片证件照/修复 | 文件 + 画布直接操作 | 操作前后或页面预览 | 编辑预览→应用 / 导出 | 必须手算坐标而不能看到效果 |
| `batch-processor` 批量处理 | PDF 合并、压缩、批量格式转换 | 文件清单/顺序 + 操作设置 | 每项状态、体积、产物和错误 | 确认执行→队列/进度→查看/保存 | 只显示一个不明确百分比或丢失失败项 |
| `guided-workflow` 引导流程 | 发票整理、OCR 表格复核 | 分步选择/预检/人工确认 | 可核对清单与提交报告 | 下一步/上一步/确认/撤销（有能力时） | 在未经预览和授权时批量归档 |

一个工具可以组合主模式和辅助模式，例如 OCR 表格是引导流程 + 结构结果编辑；PDF 裁剪是可视化编辑 + 批处理导出。**主模式由任务决定，不由字段 `textarea` 或 `layout: text` 推导。**

## 2. 自动运行与副作用

工具的节奏由 catalog 的 `experience.execution` 声明（旧的 `interaction` 字段已于 2026-10-13 删除，catalog 与 Rust/TS 契约里都不再存在，避免两处节奏描述互相矛盾）（`packages/core/catalog/*.json`，见 [RFC-0001](../rfcs/0001-tool-experience-contract.md)），`useToolDraft` 与 `ToolPage` 都从它取值；新增工具没有声明就无法通过 `pnpm rust:test` 的 catalog 契约检查。

- `live`：确定性、廉价、纯本地变换；输入有效时立刻更新（当前实现约 120ms 合并键入）。不要因错误输入保留看起来有效的旧结果——现在会显示「上一次有效输入」提示。机械规则：`live` 不允许出现在有外联、`multiFile` 或 `generator` 类工具上。
- `debounced`：复杂解析、大文本、但没有持久副作用的计算（当前实现 350ms）；运行按序链接，过期结果不会覆盖较新结果。
- `manual`：网络、哈希大文件、OCR、大图模型、批量处理、文件写入、原生系统探测、耗时密钥操作；用户必须主动发起，页面显示运行按钮而不是实时提示。
- **生成例外**：随机密码/UUID 可以首次自动给出一个样例，但调整长度、字符集等参数时，若会替换用户正阅读或复制的随机值，应由明确“重新生成”按钮驱动，或保留上一结果直到新值就绪。计时器 TOTP 则按时间窗口刷新且标记过期时间。
- **空值/非法值**：提示用户下一步，不能触发昂贵计算；上次结果必须清空或用「来自上一输入」标识，禁止不带说明地继续可复制。
- **异步竞态**：每次用户输入增长 `generation`；只有当前 generation 可提交结果，销毁页面后不得写旧状态。
- **设置影响**：输出格式、页码、画质、日期格式等选项修改，应能让用户理解单位与结果变化；高级设置有“恢复默认”。

## 3. 统一页面结构（按模式选择）

```text
面包屑 / 工具标题 / 一句话任务 / 运行范围或联网提示
├── 主工作区
│   ├── 输入：拖拽文件 / 直接编辑 / 主参数 / 画布
│   └── 结果：可复制值 / 匹配高亮 / 结构详情 / 预览 / 产物
├── 次级选项：高级参数、例子、单位、输出格式
└── 状态与动作：重试 / 取消 / 下载 / 另存 / 打开位置
```

- 运行按钮在手动工具的主操作路径上，且固定拥有可理解的语义（例如“合并 3 份 PDF”“导出裁剪后的图片”）。
- 当屏幕较窄时，输入→结果→高级选项按阅读顺序排列，避免远离输入的按钮与结果。
- 文件工具在提交前展示输入文件数、大小、顺序（若有影响）、输出格式/位置、磁盘写入范围；源目录写入的首次授权必须显式。
- 优先呈现可使用结果，文件名/大小作为辅助元数据；结构数据应可复制字段、复制全部和导出。

## 4. 七类模板的具体验收

### 4.1 即时转换 / 结构解析

- 左输入右输出，允许复制、交换方向（支持双向时）、粘贴样例、清空和格式化；错误定位到行/列/字段。
- JWT 分离 Header、Payload、Signature；**解析不代表验签成功**，验证须显示“已验证/未验证/未提供密钥”状态，不把 unverified payload 标为可信。
- 正则工具高亮所有匹配并列出捕获组及替换预览；对复杂正则设时间/输入长度预算，避免阻塞。
- X.509 展示有效期、主体/签发者、指纹与链信息；错误或未验证的证书不能只显示绿勾。
- 结果由内容类型选择视图，不依赖诸如 `password-gen.txt` 文件名来判断呈现策略。

### 4.2 计算分析 / 生成器

- 时间工具可见输入/输出时区、时间单位，明确 epoch 秒/毫秒；Cron 列出未来 N 次发生时间并标明时区/夏令时。
- 日期差明确起止是否包含当日、周末及假日规则；子网工具明确网络地址/主机范围/掩码；颜色工具有色块对照。
- 生成器显示生成条件及批量数量，每条结果独立复制；敏感值默认不持久化、日志不得记录明文。
- TOTP 包含倒计时与周期结束处理；时间源异常时不可显示“仍有效”。

### 4.3 可视化编辑 / 批处理 / 引导流程

- **裁剪/旋转/证件照**：优先直接操作预览，参数与画布双向同步；可撤销和重置，预览与导出算法保持一致。
- **PDF 合并/组织/拆分**：按文件与页显示可识别缩略图，顺序可拖动或键盘调整；说明书签/表单等已知保真限制。
- **图片压缩**：显示原图与压缩后效果、尺寸/质量/体积差值；不能把文件更小等同于保真更好。
- **OCR / 发票整理**：来源选择→预识别/预检→表格/字段人工修正→输出或归档；扫描件 OCR 不可默认为完整可信。
- **批处理失败**：每个文件有成功、失败与原因；允许按失败项重试，不应整批悄悄标记成功。

## 5. 状态、错误与反馈

| 状态 | 用户看到什么 | 允许操作 |
| --- | --- | --- |
| `idle` | 样例/提示，输出空态 | 选择输入或粘贴 |
| `invalid` | 具体字段错误与修复建议 | 修正输入；禁用无效提交 |
| `preparing` | “读取/解析/生成预览”，可预期反馈 | 可取消时显示取消 |
| `running` | 阶段、进度（如可测）、运行时信息 | 取消；高风险操作需阻止重复提交 |
| `staging` | 写入临时与输出目录的区分 | 不得误报处理已完成 |
| `succeeded` | 可立即使用的结果、目标路径、摘要和警告 | 复制、预览、下载、再次运行 |
| `failed` | 稳定错误码、可理解消息、恢复动作、保留输入 | 修改选项、重试、复制诊断 |
| `cancelled` | 已取消且不会继续发布成功；若 Native 未取消需明确状态 | 重新运行 |
| `stale` | 上次结果过期/与当前输入不匹配 | 更新或重新执行 |

不可用状态不能只以颜色提示；任务消息应可被屏幕阅读器感知，且不要在每个进度小数变化时重复播报。

## 6. 安全、无障碍与平台

- 输入框与结果区具备清楚标题/关联标签；按钮可触达，焦点回到合理位置；拖拽排序有键盘替代。
- 控件边界用 `--ui-control-line`，装饰线用 `--ui-line`；浅/深色模式和 860px 最小桌面宽度外加窄屏 Web 必须检查截断与溢出。
- Web 不得显示只有 Tauri 特权才能运行的操作为普通可运行按钮；Win7 壳属于浏览器功能集，须另列 EOL 风险。
- 文件保留在本地属于产品目标，但 DNS/IP 查询会接触外部服务；界面必须准确提示外部请求的类型及发送的数据。
- 不能把自动另存、发票整理、删除、清理隐藏在「实时计算」里；数据破坏性操作需用户授权、清晰回退与可恢复路径。

## 7. 设计评审表

对每个工具记录：原用户任务、主输入、主结果、模型、执行节奏、默认值、异常/隐私、Web/Tauri 限制、键盘支持、首次使用成功路径、真实文件测试、迁移影响。结论必须标记 **Observed/Target/Verify/Verified**。静态 catalog 审计只建立假设，不能代替可用性测试。
