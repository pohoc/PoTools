## 状态与优先级

- **现状（Observed）**：可从已引用的代码或 catalog 直接核对；不等于已经做过 GUI 实测。
- **目标（Target）**：后续 PR 应实现的行为；未落地之前不得写为已支持。
- **待验证（Verify）**：需要浏览器、Tauri、真实文件或发布包实测才能确认。
- **已验证（Verified）**：需要列明版本、系统、命令、样例、输出证据。
- **阻断（Blocker）**：权限越界、数据损坏、不可逆误操作、严重敏感数据泄露；在同类新功能扩展前优先修复。

规范冲突时：安全规则优先于视觉/交互偏好；协议与运行行为以实际 Rust/TS 代码为准；UX 的未来目标以本目录 `standards/TOOL_INTERACTION.md` 为准；`docs/plans` 不得覆盖最终约定。变更决策时，同步更新适用文档和 [差距登记](audits/IMPLEMENTATION_GAPS.md)。

## 文档维护工作流

1. 先写使用场景、工具分类、数据权限与成功标准，再设计字段或页面。
2. 更新工具 catalog / 引擎 / adapter 时，同时更新工具矩阵与契约文档；破坏性变更需 RFC/ADR。
3. 工具完成测试后，矩阵中才可由「待验证」变更为「已验证」，留下测试命令、系统和样例。
4. 每个修改工具行为的 PR 应说明浏览器 / 桌面能力差异；涉及特权服务的 PR 必须有授权失败测试。
5. 文档更新也应校验路径、相互链接、表格项数量和实际脚本名称。

## 本次文档 PR 的范围

本 PR 只建立统一开发标准、交互标准、98 项逐项 UX 改造方向与验收基线；**不改变 Rust / React / Tauri 的运行代码**。矩阵中的「目标交互」不是当前功能声明，整改任务应分成可独立测试的小 PR。
